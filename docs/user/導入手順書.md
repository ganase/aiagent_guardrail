# 導入手順書（v0.2）

## 目的

AI Agent を標準構成で導入し、利用環境の分散、古い設定の残存、未承認接続を防ぐ。

---

## 1. 導入前確認

| 確認項目 | 内容 |
|---|---|
| **対象端末** | 業務で利用する会社管理 PC であること |
| **利用目的** | 個人試行・チーム内利用・部内業務利用のどれかを確認する |
| **OS / 環境** | Windows 11 を推奨 |
| **権限** | **原則必須: 管理者権限で実行**（ACL 保護と Claude Code managed-settings のシステム配置に必要） |
| **外部接続** | 未承認 MCP、Plugin、個人契約 API、未承認 SaaS を使わない |
| **機密情報** | 機密情報・認証情報・本番データを投入しない前提で始める |
| **プログラムランタイム** | Python、Node.js 等は会社のソフトウェア導入許可リスト・指定手順に従う。GUIウィザードは未導入時に winget 経由の自動導入を提案するが、これは個人試行・評価用途の簡易手段であり、部内業務利用（Level 3）では会社の指定手順・許可バージョンでの導入を優先する |
| **ライブラリ導入** | pip / npm 等は許可済みパッケージリストと指定手順に従う |
| **Codex / Claude Code** | 標準インストーラーまたは会社指定手順で導入済みであること |

> **⚠ 非 admin 導入について**
> 非管理者でも技術的にはインストール可能ですが、以下の制約があります。
> - ACL による設定ファイル改変保護が設定されません（ユーザーが guardrail_policy.json 等を書き換え可能な状態になります）
> - Claude Code managed-settings のシステム領域への配置ができません
> - **非 admin 導入は評価・開発環境用途に限定してください。**

## 2. インストール

### 方法 A: GUI ウィザード（推奨・管理者権限不要な場合でも起動可）

1. 配布されたリポジトリを ZIP でダウンロードして任意のフォルダに解凍する
2. 解凍したフォルダ内の `SETUP.bat` をダブルクリックする
3. **初回の「AI Agent Workspace」起動時に**、共有ドライブ（Box等）の自動マウント設定ダイアログが表示される。共有フォルダのローカルパスとドライブ文字を指定するか、使わない場合は「使用しない」を選択する（選択内容は `AIAgent_Workspace\config\box_mount.local.cmd` に保存され、次回以降は表示されない）。設定を変更する場合は、リポジトリ直下の `CHANGE_BOX_MOUNT.bat` を実行する。使用する場合は選択したドライブ文字が自動的にマウントされ、以後は Windows スタートアップにも自動登録され、ログオンのたびに自動マウントされる
4. UAC（ユーザーアカウント制御）の確認画面が表示されたら「はい」を選択
5. GUI ウィザードが起動する → インストール先を確認（デフォルト: `C:\Users\<ユーザー名>\AIAgent_Workspace\`）
6. 「ランタイム / AI ツール」欄で、未導入の Node.js・Git for Windows・Python・Claude Code・Codex を確認する。未導入の場合は `winget` 経由で自動導入するチェックボックスが表示される（`winget` が無い環境では自動導入できないため手動導入が必要）
7. **「認証設定」欄は、Claude Code / Codex それぞれについて表示されます。** ラジオボタンで方式を選択してください。
   - **Gateway形式で貼り付け**: 組織指定の認証サービス の Set Up 画面で生成した内容をそれぞれ貼り付けてください（組織指定の認証サービス 専用のフォーマットです）。既存の認証情報は Claude Code / Codex ともに画面へ表示されないため、変更時は Set Up 画面から再度貼り付けてください。
   - **APIを直接指定**: Anthropic / OpenAI 互換の API キーとモデル名を入力してください（必須）。Base URL は任意で、空欄の場合は各社の公式デフォルトエンドポイントを使用します。社内 Gateway を使わない場合はこちらを選択してください。
   - いずれの方式でも、入力内容には個人の API キー等が含まれるため、他人と共有したり別の AI に入力したりしないこと
8. オプション（Claude Code 設定 / Codex 設定 / PATH 追加）を選択して「インストール実行」をクリック

> Node.js/Git/Python の自動導入は winget（`OpenJS.NodeJS.LTS` / `Git.Git` / `Python.Python.3.12`）経由です。管理者権限がない場合、権限不足でこのステップが失敗することがあります。その場合はログを確認のうえ手動導入するか、管理者に相談してください。
>
> 認証設定の入力は必須です（選択した方式に応じた必須項目が空欄のまま「インストール実行」を押すと入力エラーになります）。API キーが流出した可能性がある場合は、Gateway形式なら Set Up 画面で、API方式なら発行元の管理画面でキーを再発行し、新しい内容で `SETUP.bat` を再実行してください（再発行すると以前のキーは無効になります）。
>
> Gateway形式と API方式を切り替えて再インストールした場合、前回の設定が一部残ることがあります（詳細は [既知の限界.md §11](../admin/既知の限界.md) 参照）。切り替え後は `~/.claude/settings.json` / `~/.codex/config.toml` の内容を確認することを推奨します。

### 方法 B: コマンドライン（上級者・自動化向け）

管理者 PowerShell でリポジトリのルートから実行します。

```powershell
cd <展開先>
.\installer\install_standard.ps1 -ConfigureClaude -ConfigureCodex
```

ユーザー PATH に `ai-pip` / `ai-npm` を追加する場合:

```powershell
.\installer\install_standard.ps1 -ConfigureClaude -ConfigureCodex -AddWrappersToUserPath
```

インストールが成功すると:
- `{InstallRoot}/config/installed_hashes.csv` が生成されます（改ざん検知用）
- ACL が設定され、Users の書込権限が制限されます
- Claude Code managed-settings に `run_guardrail_hook.cmd` 経由の hook が配置されます

## 3. 導入後の確認

```powershell
.\installer\check_status.ps1
```

スモークチェックが実行され、allow / ask / deny / 危険コマンド / blocked_path の各動作が確認できます。

| 確認項目 | 確認内容 |
|---|---|
| **標準版** | 指定された標準版が入っている |
| **設定ハッシュ** | 標準設定・Hook本体・テンプレートが改変されていない（`installed_hashes.csv` とSHA256を再計算して照合。`check_status.ps1` の「Hash integrity check」欄で確認） |
| **ACL保護 / 導入レベル** | 管理者導入（ACL保護あり）かどうかを `check_status.ps1` の「ACL protection / install level」欄で確認。Level 3（部内業務利用）には管理者導入が必須 |
| **外部接続** | 許可されていない接続先が追加されていない |
| **Sandbox** | AI Agent が操作できる作業フォルダ・実行範囲が限定されている |
| **ライブラリ導入制御** | `pip install` / `npm install` 等が Hook 経由で確認される |
| **ログ** | 導入状況・エラー・拒否イベントを確認できる。ワークスペースランチャーから起動した Codex / Claude Code の操作履歴・セッションログは Box の個人用 `Sandbox\<ユーザー>\AI-Agent-Audit` に同期される（認証情報・設定は同期しない） |

## 4. ライブラリ導入確認

Codex / Claude Code 等の実行中にライブラリ導入を提案される場合の対応:

| 区分 | 対応 |
|---|---|
| **プログラムランタイム** | 会社のソフトウェア導入許可リスト・指定手順に従う。許可外は導入しない |
| **許可済みライブラリ** | deny リストに該当しない場合は導入できる。組織の別ルールがある場合はそちらを優先する。 |
| **未審査ライブラリ** | deny リスト外ならガードレール上は許可される。必要な社内承認は別途確認する。 |
| **禁止・typosquat 疑い** | ガードレールがブロック（exit 2）。個人判断で回避しない |
| **ガードレール停止時** | Hook で止まった導入を別コマンドや設定変更で回避しない |

```powershell
# 許可済みの例（自動許可 = ALLOW、ダイアログなし）
ai-pip install pandas

# deny リスト外の未知パッケージ（自動許可）
ai-pip install some-new-library

# 禁止パッケージ（ブロック = DENY）
ai-pip install example-malicious-package
```

## 5. Claude Code での動作確認

Claude Code が Bash で pip install を提案したとき:
- allowlist 済みパッケージ → 無音で自動承認（ダイアログなし）

- deny / typosquat 疑い → ブロック（Claude にエラーメッセージが返る）

## 6. セルフ・セキュリティ・チェック

ローカルリポジトリに仕組みができた場合は、チーム共有・組織指定のGit基盤 への push・部内業務利用へ進む前に、セルフ・セキュリティ・チェックを実行する。

| 手順 | 作業 | 補足 |
|---|---|---|
| **1** | チェック手順書（組織指定のリポジトリ）を確認する | 実行コマンドはリポジトリ側の記載を正とする |
| **2** | チェック対象のローカルリポジトリを確認する | 対象は AI Agent で作成したコード・設定・README・依存関係ファイルを含む作業フォルダ |
| **3** | セルフ・セキュリティ・チェックを実行する | 実行できない場合やエラー内容が分からない場合は管理者に相談する |
| **4** | 指摘事項を確認し、必要に応じて修正する | Secret 混入・危険な実装・不要ファイル・依存関係の問題を確認する |
| **5** | 修正後に再実行する | 指摘が解消しない場合は、個人判断で共有・push・業務利用へ進めない |
| **6** | 実行したことを README またはレビュー記録に残す | Level 2 以上では共有時、Level 3 では承認時の確認材料にする |

チェックは安全性を完全に保証するものではない。検出できない設計不備や業務上の妥当性は、人間レビューで確認する。

---

## 7. 改ざん検知について

正式インストールでは hook 起動時に `config/installed_hashes.csv` の存在・可読性・SHA256を照合します。欠落、不読、または改ざんは claude-hook モードで exit 2（ブロック）になります。定期的に `check_status.ps1` で整合性を確認してください。

| 手順 | 作業 |
|---|---|
| **1** | 更新案内で、対象者・更新理由・期限を確認する |
| **2** | 新しい標準インストーラーを実行する |

## 9. トラブル時

| 状況 | 対応 |
|---|---|
| **インストールできない** | エラー内容・端末名・実行日時を記録して管理者へ連絡する |
| **設定ハッシュが違う（改ざん検知）** | 標準設定から外れている可能性があるため、再導入または管理者確認を行う |
| **外部接続を求められる** | 個人判断で許可せず、利用目的と接続先を確認する |
| **高額・長時間処理になりそう** | 実行前に止め、費用影響を確認する |
| **Sandbox が有効か分からない** | 作業範囲・実行範囲の確認方法を管理者に確認する |
| **セルフ・セキュリティ・チェックが実行できない** | エラー内容と対象リポジトリを記録し管理者へ相談する |
| **ガードレールが意図せずブロックする** | コマンドと出力を記録し、管理者または AIガバナンスチームに相談する。自己判断で hook を無効化しない |

## 10. 作業場所と導入後確認

導入後は、作業フォルダを管理された共有ワークスペース配下に作成してください。Box、OneDrive、SharePoint、Google Drive、組織指定の共有フォルダ等を利用でき、Boxはその一例です。

ワークスペースランチャーから Codex または Claude Code を終了すると、生ログが `Sandbox\<ユーザー>\AI-Agent-Audit\Codex` または `ClaudeCode` に同期されます。起動前にも前回分を補完同期します。認証情報・設定ファイルはコピーされません。同期に失敗してもローカルのログは削除されないため、Box の接続を確認して次回起動してください。

1. `check_status.ps1` を実行し、設定・ハッシュ・ACL保護の状況を確認する。
2. 対象ワークスペースに `AGENTS.md` または `CLAUDE.md` を配置し、利用するAgentが方針を参照できることを確認する。
3. ワークスペース外の編集・削除・移動は、対象と理由を確認してから行う。
4. bypass、auto approval、危険モードは使用しない。警告の意味が不明な場合は作業を停止して管理者へ相談する。
