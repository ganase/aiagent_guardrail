1システム構成図配布物・実行時の呼び出し関係

標準インストーラーが1台のPCに配布するファイル一式と、Claude Code / Codex から実行時にそれらがどう呼ばれるかを示します。ガードレールの実体は「JSON設定＋1本のPythonスクリプト」で、Claude Code の Hook 機構から都度呼び出されます。

配布・インストール 設定ファイル（判断材料） 実行時Hook本体 ログ・監査 ブロック時の到達点
読み方のポイント Hookの実体は1本のPythonスクリプト（aiagent_guardrail_check.py）で、Claude Code の managed-settings から起動します。危険コマンド・ランタイム導入・パッケージ導入・機密ファイル読取・Credential検知・変更回数制限をこの1本が担い、判断材料はJSON設定として外部化されています。Codexには同等のHookはないため、Windows Sandbox、approval_policy、ai-pip/ai-npm経由の依存導入チェックで補完します。素のpip/npmは直接検査されません。

23層判定ロジックdeny-list-only 方式

パッケージ導入（pip / npm 等）の判定は「denyリストに載っているものだけブロックし、未知は通す」方式です。allowlist の維持コストを抑えつつ、既知悪性パッケージと類似名（typosquat）を確実に止めます。

decision値意味結果
allowallowlist上で status=allow / review、または未知で類似名なし無音で通過。ログに記録
denyallowlist上で status=denyexit 2 でブロック、理由を表示
deny(typosquat)既知名とのLevenshtein距離1〜2exit 2 でブロック、類似名を提示
deny(expired)expires_atが過去日付（審査期限切れ）exit 2 でブロック、再審査を依頼
（PostToolUse警告）ツール出力にCredential形式を検知ブロックせず警告のみ（操作は完了済み）

3利用者ワークフローClaude Codeを使う人が実際に見る流れ

利用者は自分でガードレールを操作しません。普段どおりClaude Code / Codexに指示するだけで、危険な操作の手前で自動的に介入されます。よくある3つの場面での見え方は次のとおりです。

A. 許可済みライブラリを入れる

  1. Claude Codeに「pandasを使って集計して」と依頼
    Claude Codeが pip install pandas を提案
  2. Hookが自動判定
    allowlist に allow 登録があるため即許可。allow
  3. そのまま実行される
    利用者には確認ダイアログが出ない（無音で通過）

B. 未知・禁止パッケージを入れようとする

  1. Claude Codeが未知のパッケージ導入を提案
    例: pip install pandsa（タイプミス）
  2. typosquat検知でブロック
    既知の pandas に類似 → deny。Claude の画面にエラーとして表示される
  3. 利用者が対応
    正しいパッケージ名なら訂正して再依頼。判断に迷えばAIガバナンスチームへ相談（自己判断で回避しない）

C. 機密ファイルを読ませようとする

  1. Claude Codeが .env の内容を読もうとする
    例: デバッグのため cat .env を実行しようとする
  2. blocked_pathsでブロック
    機密ファイルパターンに一致 → deny。内容は一切表示されない
  3. 安全な代替を使う
    .env.example 等のテンプレートファイルで代用するか、値を直接貼らずに管理者に相談する
利用者が気づかないうちに動いているもの 同一セッションでのファイル変更（Edit/Write）が60分間に100回を超えると警告、200回を超えると変更操作のみ停止します（Read・通常の会話は継続可能）。無限編集ループや暴走的な繰り返し処理に気づくためのセーフティネットで、Codexでは発動しません（Hook機構が無いため）。

4導入手順SETUP.bat から動作確認まで

管理者権限での導入が原則必須です（ACL保護・Claude Code managed-settings のシステム配置に必要）。非admin導入も技術的には可能ですが、評価・開発用途に限定してください。

1

ZIPを展開して SETUP.bat を実行

GitHubからリポジトリをZIPで取得し、任意のフォルダに解凍。SETUP.bat をダブルクリックすると、共有ドライブの初回設定（Box等、使わない場合はスキップ可）→ 自動マウント → UAC確認 → GUIウィザード起動まで自動で進みます。

2

UACで管理者権限を許可

「はい」を選択して管理者として再起動。拒否した場合は非admin導入となり、設定ファイル改変の保護（ACL）が適用されません。

3

ランタイム・AIツールの導入状況を確認

GUIウィザードが Node.js / Git for Windows / Python / Claude Code / Codex の導入状況を検出。未導入分は winget 経由の自動導入を選択できます（wingetが無い環境では手動導入が必要）。

4

認証設定を入力する（必須）

Claude Code / Codex それぞれで「Gateway形式で貼り付け」（社内 AI Gateway の Set Up 画面で生成した内容）か「APIを直接指定」（Anthropic / OpenAI 互換のAPIキー・モデル名。Base URLは任意）を選択して入力。必須項目が空欄では「インストール実行」がエラーになります。この内容は他人と共有しないこと。

5

「インストール実行」をクリック

下記が配布・適用されます：guardrails/（config・hooks・templates・bin）、Claude Code managed-settings.json、ACL保護（管理者導入時）、installed_hashes.csv（改ざん検知の基準）。

6

導入後の動作確認

installer\check_status.ps1 を実行。allow/deny/危険コマンド/blocked_pathのスモークテスト、ハッシュ整合性、ACL保護状態、Codexのapproval_policy設定、直近のファイル変更回数・トークン使用量まで一括確認できます。

コマンドラインでの導入（上級者・自動化向け）

管理者PowerShellでリポジトリのルートから実行します。

cd <展開先>
.\installer\install_standard.ps1 -ConfigureClaude -ConfigureCodex

# ai-pip / ai-npm をユーザーPATHに追加する場合
.\installer\install_standard.ps1 -ConfigureClaude -ConfigureCodex -AddWrappersToUserPath

# 導入後の確認
.\installer\check_status.ps1

5何を守り、何を守らないか

本ガードレールは「完全なセキュリティ」ではなく「善意のAIエージェントに対する摩擦と監査ログの提供」です。詳細は docs/admin/既知の限界.md を正としてください。

守れるもの

Claude Code から提案された危険コマンド・再帰削除対応
Claude Code から提案された禁止・類似名パッケージ導入対応
Bash / Edit / Write 経由の既知の機密ファイルパターン読取対応
プロンプト・ツール出力中の既知形式のAPIキー等対応
設定ファイル・Hook本体・テンプレートの改ざん対応（ACL保護時）

守れないもの

python -cやスクリプト経由での回避未対応
Codexが素の pip/npm を直接実行する場合未対応
利用者がターミナルで直接実行するコマンド未対応
未知パッケージそのもの（deny-list-onlyの設計上）部分対応
推移的依存（間接的な依存パッケージ）未対応
本資料はソースコード（guardrails/hooks/aiagent_guardrail_check.py 他）・設定JSON・docs/admin/ 配下の設計文書を基に作成した補助資料です。内容に矛盾がある場合は各正式文書（ガードレール設計.md／運用設計書.md／既知の限界.md／導入手順書.md）を正としてください。
